## Done
- "Nova rehabilitacija" button on `/nurse` → `/nurse/odpust`, 7 steps, one per screen:
  1. Davčna številka → existing patient is reused ("Nova rehabilitacija se mu bo pojavila v aplikaciji"), new one asks for name; občina / naselje / naslov (prefilled for existing). Warning if they already have an open rehabilitacija.
  2. Template (6 cards).
  3. Patient values (template defaults, e.g. 130/80) + check-in questions pre-ticked, max 6 daily enforced.
  4. Medicines: template's recommended ones merged with what the patient already takes (medicines of their previous rehabilitacija), tick + dose chips + time chips, "Uredi" for a custom dose, "Dodaj zdravilo" from a mock list (all templates' medicines), "Odstrani" for added ones. Staff notes (`zdravilaOpomba`, `kdaj`) shown; "po potrebi" medicines need no time.
  5. Exercises (pre-ticked) + end date (template default length).
  6. Patronažna sestra suggested by teren (naselje-specific teren wins, nadomeščanje → substitute), one tap "Potrdi predlog", or another nurse, or "Nedodeljeni".
  7. Summary → "Odpri rehabilitacijo".
- Server: validates everything, `ensurePatientAccount` (T-38), saves address, rehabilitacija, medications with `change` (novo / spremenjeno + previous_dose / nespremenjeno / ukinjeno vs the previous rehabilitacija), exercises, `audit_log` ("odpri_rehabilitacijo"). Always redirects to the result page, so a retry can't open a second one.
- `/nurse/odpust/<rehabId>`: "Rehabilitacija odprta ✓", "Natisni prijavni listek" for a new patient (T-38 listek, never on the odpustnica), "Podaljšaj" (later end date; reopens one that ended ≤ 14 days ago; stores the original end in `patient_values.prvotniKonec` so the patient's ring says "Okrevanje podaljšano do …"; audit_log), "Nova koda QR" (T-38 button).
- Checked: nurse suggestion, medicine merge/diff and default end date with a throwaway test; every step at 390 px and 1440 px with sample data; logged-out redirects. **Not tested against the database** (no `.env.local` on this machine).

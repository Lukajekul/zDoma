## Done
- QR token = starting password. A row in `patient_qr_tokens` means "still on the starting password": `requireProfile()` sends non-staff users to `/prijava/geslo` ("Nastavite svoje geslo", two fields, min 8 chars, not the davčna).
- Saving the password (`setOwnPassword` in `src/lib/qr/accounts.ts`, admin API) deletes the token row, so the QR stops working and can't be reprinted; audit_log `password.set`. "Nova koda QR" still makes a new starting QR.
- New patient login `/prijava/pacient` (QR steps + davčna/geslo form); logged-out `/patient/*` redirects there; staff login links to it.
- `/demo` stores no token, so the judge demo skips the password step.
- AGENTS.md §6, README and `docs/demo-accounts.md` updated.
- Checked end to end with a throwaway patient (deleted): QR → /prijava/geslo, guard, short-password error, save → home, token gone, old QR refused, own-password login works.

## Notes for other agents
- No migration. New exports in `src/lib/auth.ts`: `PATIENT_LOGIN_PATH`, `SET_PASSWORD_PATH`. Pages that use `getCurrentProfile()` instead of `requireProfile()` skip the forced password step.
- Seeded demo QRs in `docs/demo-accounts.md` stop working once someone sets a password through them (re-run the seed or "Nova koda QR").

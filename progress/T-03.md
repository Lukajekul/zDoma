## Data model (build against this)
Row types in `src/lib/types.ts` mirror the tables exactly (snake_case, as the Supabase client returns them).
- **profiles** (1 per auth user, `id = auth.users.id`): davcna, first_name, last_name, is_staff, address, obcina, naselje, phone, photo_url, checkin_time ("08:00"). Created automatically by a trigger on sign-up; davcna comes from the login email `<davcna>@zdoma.local`, names from `user_metadata.first_name/last_name`. `is_staff` only via service role/seed.
- **rehabilitacije**: patient_id, template_id (`TemplateId`), diagnosis, status `aktivna|zakljucena`, start_date, end_date, created_by, assigned_nurse_id (null = "Nedodeljeni"), questions (text[] of template question ids), patient_values (jsonb, e.g. `{suhaTeza: 72}`), lace (jsonb `{l,a,c,e}`), current_status (`zeleno|rumeno|rdece`, for dashboard sort), installed_at (T-36).
- **tereni**: nurse_id, obcina, naselja[], postcodes[]. **nadomescanje**: nurse_id, substitute_id, until_date.
- **family_access**: requester_id, patient_id, status `pending|approved|rejected`, relation ("hčerka"), decided_at. Request it with RPC `request_family_access(p_davcna, p_relation)`: always succeeds silently, so it never reveals whether the number exists.
- **medications**: rehab_id, name, active_substance, dose, times (`zjutraj|opoldne|zvecer|ponoci`[]), purpose, change (`novo|spremenjeno|nespremenjeno|ukinjeno`), previous_dose, photo_url, start/end_date. (T-31 adds pick-up fields in its own migration.)
- **dose_logs**: medication_id, rehab_id, scheduled_date, time_of_day, status `vzeto|izpusceno`, entered_by. Unique per medication+date+time.
- **checkins**: rehab_id, checkin_date, answers (jsonb `{questionId: value}`), same_as_yesterday, triage_status, reasons[], photo_path, entered_by. **One per rehab per day** (unique).
- **rehab_exercises**: rehab_id, exercise_id (template id), title, repetitions, times_per_day, active. **rehab_logs**: rehab_exercise_id, rehab_id, log_date, done, pain 0–10, entered_by.
- **alerts**: rehab_id, checkin_id, status `rumeno|rdece`, reason (always), source `checkin|zdravila|brez_pregleda|drugo`, state `odprto|zaprto`, action, resolved_by/at.
- **audit_log**: actor_id, action, entity, entity_id, details jsonb. Insert-only, staff read.
- **staff_directory** (view): id, first_name, last_name, photo_url of staff, readable by any logged-in user (nurse name on "Danes").
- Storage bucket **wound-photos** (private), path `<rehab_id>/<file>`.

## Access rules (RLS)
- Patient: reads own profile and everything of own rehabilitacije; inserts dose_logs, rehab_logs, checkins, alerts for own active rehab.
- Approved zadolženec: reads the patient's profile and rehabilitacije data; inserts dose_logs, rehab_logs, checkins with `entered_by = self`. Can't change anything else or undo the patient's entries.
- Anyone may delete only log rows they entered themselves (undo "Vzeto"). Check-ins can't be edited.
- Staff (`is_staff`): read everything, write rehabilitacije, medications, exercises, tereni, nadomescanje, alerts.
- `entered_by` defaults to `auth.uid()` and must equal it on insert.

Sign-ups with `<davcna>@zdoma.local` can't be confirmed, so turn it off in the dashboard (Authentication → Sign In / Providers → Email → Confirm email) or create users server-side with `email_confirm: true`.
- For the generated types use `Tables<"profiles">` etc. from `@/lib/database.types` with the Supabase client; `types.ts` gives the narrower unions (TemplateId, TimeOfDay…) for app code.
